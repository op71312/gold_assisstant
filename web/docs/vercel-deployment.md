# Vercel Services deployment

## What runs where

- **Vercel frontend service:** Next.js UI, read-only project-data APIs, status check, and authenticated streaming proxy at `POST /api/agents`.
- **Vercel `gaib-runtime` service:** FastAPI and the static GAIB-1 Python pipeline; it loads repository artifacts and calls ThaiLLM, Cloudflare, Qdrant, and Jina.
- The runtime does not open or execute `.ipynb` files. Notebook files remain research/evaluation sources.
- The Python service has no public route. The frontend calls it through a private Vercel service binding.

This deployment uses no application database or persistent disk. Qdrant remains an external vector database required by the selected RAG pipeline. [`render.yaml`](../../render.yaml) is an optional alternative for hosting only the Python runtime on Render.

## Deploy both services

1. Push the repository to GitHub, including `web/package-lock.json`, root `requirements.txt`, the generated `web/data/` snapshots, and runtime artifacts listed in root [`vercel.json`](../../vercel.json).
2. In Vercel, import the repository and keep **Root Directory** at the repository root. Do not set it to `web`; the root `vercel.json` defines both services.
3. Vercel reads `vercel.json`: `frontend` builds the Next.js app from `web/`; `gaib-runtime` builds FastAPI from the repository root using the lean root `requirements.txt`. Keep the Python `installCommand` unset so Vercel can optimize the function bundle. The Python function uses versioned CSV data and excludes Parquet files, research-only notebooks, raw news, embeddings, and benchmark outputs; only the required feature/simulator/model/RAG artifacts are packaged. The root rewrite sends all public requests to the frontend, while the backend is reachable only through its binding.
4. Add these environment variables in the Vercel project for Production and Preview environments that should call the providers:

   | Variable | Value |
   |---|---|
   | `GAIB_SERVICE_TOKEN` | High-entropy shared secret used by the frontend and Python service |
   | `THAILLM_API_KEY1`–`THAILLM_API_KEY7` | ThaiLLM API keys; at least one key is required |
   | `THAILLM_MODEL` | `OpenThaiGPT-ThaiLLM-8B-Instruct-v7.2` (Config; exact ID from ThaiLLM `/models`) |
   | `CLOUDFLARE_ACCOUNT_ID` | Cloudflare account ID for embeddings |
   | `CLOUDFLARE_API_TOKEN` | Cloudflare API token for embeddings |
   | `QDRANT_URL` | Existing Qdrant vector collection endpoint |
   | `QDRANT_API_KEY` | Qdrant authentication |
   | `JINA_API_KEY`, `JINA_API_KEY2`–`JINA_API_KEY4` | Jina reranking keys; at least one key is required |

   Add `GAIB_SERVICE_TOKEN` under **Vercel → Project → Settings → Environment Variables** for each environment you deploy (Production and Preview as needed). Generate a high-entropy secret and use that same value for both the frontend and Python service; Vercel project environment variables are shared across services. Save it as a secret and redeploy. `GAIB_RUNTIME_URL` is generated by the service binding; do not set it manually. The binding is private but does not authenticate requests, so `GAIB_SERVICE_TOKEN` remains required. Never expose secrets with a `NEXT_PUBLIC_` prefix.

5. Deploy. Confirm that both services build successfully before testing the app.
6. In the Vercel project, open **Settings → Analytics** and enable Web Analytics. The app already includes the `<Analytics />` component; the Analytics dashboard reports page views/visitors, while the app's Python status panel checks backend health.

## Data snapshots and API functions

`next.config.ts` uses `outputFileTracingIncludes` to package the required files from `web/data/` into the corresponding server functions:

- `/api` and `/api/data`: manifest
- `/api/data/market`: market history snapshot
- `/api/data/portfolios`: portfolio catalog
- `/api/data/portfolios/[portfolioId]`: manifest and yearly portfolio snapshots

These are read-only, versioned files; no application database or writable disk is required. Re-export and commit the snapshots when the source Parquet data intentionally changes.

## Verify the deployment

1. Open `https://<your-vercel-domain>/api`. Expect `status: "ok"` and `gaibRuntimeConfigured: true`.
2. Open `/api/data`, `/api/data/market?limit=5`, and `/api/data/portfolios?limit=5`. Confirm the endpoints return the expected snapshots.
3. Submit a non-sensitive question through Gold Assistant and confirm streamed agent events and the final citation-checked report appear.
4. If the status says `not_configured`, use its message to see whether `GAIB_RUNTIME_URL` (binding) or `GAIB_SERVICE_TOKEN` is missing. Confirm the binding in the deployed `vercel.json`; set the token under Vercel project environment variables and redeploy. If the AI request still fails, check the frontend and Python service logs and confirm provider credentials. A missing backend configuration must remain an explicit error.
5. In **ถาม Gold Assistant**, use the Python runtime status panel to check whether the backend is ready, starting/cold-starting, missing configuration, or unavailable. It retries a few times while starting and can be checked manually. A healthy `/health` confirms the Python process and shared token only; a real question is still needed to verify external AI providers and the complete pipeline.

The agent route and Python function allow up to 300 seconds per invocation. Vercel plan limits still apply; a long provider call or cold start can time out. Check the actual request duration and plan limits before relying on long-running requests.

## Security notes

- Keep all API keys and `GAIB_SERVICE_TOKEN` in platform environment settings, never in source or browser-visible variables.
- The browser calls the same-origin Next.js proxy; it does not receive the backend token.
- The Python service has no public rewrite. `/health` is used by the server-side status route over the private binding; the agent endpoint additionally requires the shared bearer token.
- Python is pinned to 3.12 through the root `.python-version`. The latest deployment log for this project reported a 225 MB function limit; limits can vary by plan and runtime, so use the deployment's own error/output as authoritative. Keep research files excluded and avoid a custom Python install command. The RAG chunk corpus alone is about 47 MB.

## Optional Render backend

If the Python service does not fit the selected Vercel plan, deploy [`render.yaml`](../../render.yaml) as an alternative. Remove the `gaib-runtime` service and its frontend binding from `vercel.json`, set `GAIB_RUNTIME_URL` manually in Vercel to the Render service URL, and set the same `GAIB_SERVICE_TOKEN` on both platforms.
